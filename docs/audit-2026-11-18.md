### Points forts
- Découpage net : orchestrateur court (113 lignes) + une skill par phase (≤ 80 lignes) + un CLI
  déterministe (`ff.mjs`) pour tout ce qui doit être exact (état, base, inventaire, commit, attente
  de déploiement). La logique fragile n'est pas laissée à la prose.
- Progressive disclosure appliquée : détails dans `skills/ff-shared/references/`, lus à la demande.
- Sécurité d'exécution soignée : `execFileSync(cmd, argv)` partout, aucune interpolation shell,
  mot de passe de recette jamais écrit, trois gates explicites avant toute publication.
- Zéro dépendance npm, 50 tests `node:test`, manifest minimal et valide.
- Aucun agent ni skill perso embarqué : appel par nom + inventaire qui signale absents et
  inutilisables.

### Points critiques à adresser
- Sortie de `ff.mjs inventory` volumineuse (~16 Ko, ~4 000 tok) injectée au démarrage et à chaque
  reprise (P1, ouvert — changement de contrat du CLI, laissé au contrôleur).
- Pas encore de rodage réel : déclenchement, enchaînement des phases et worktree jamais exercés
  sur un vrai dépôt (P2, voir `docs/rodage.md`).

#### Explications & exemples

**#6 (corrigé).** Les sous-skills de phase sont `user-invocable: false` mais restent visibles du
modèle : leur description est payée à chaque tour. Leurs phrases-déclencheurs (« implémente
WEBFRONT-123 ») invitaient en plus Claude à les appeler hors orchestrateur, donc sans la mise en
place de l'étape 4 (`cd` dans le worktree, inventaire en contexte).

Avant :
```yaml
description: Phase implement de front-flow — confie le plan validé à l'agent d'implémentation du mapping (vue-developer ou son repli) avec brief.md, plan.md et le rapport de recette à corriger, puis lance config.verify jusqu'au vert avant de passer en phase pr. Invoquée par l'orchestrateur front-flow quand la phase vaut « implement » (« implémente WEBFRONT-123 », « reprends après la recette »).
```
Après :
```yaml
description: Phase implement de front-flow — dispatch de l'agent d'implémentation du mapping, puis config.verify jusqu'au vert. Appelée par l'orchestrateur front-flow seulement ; ne pas invoquer directement (passer par front-flow:front-flow).
```
(`disable-model-invocation: true` n'est pas une option : l'orchestrateur appelle ces skills par
l'outil `Skill`.)

**#7 (ouvert).** Mesure réelle dans ILokYou-Site : 15 993 octets, 152 entrées `available`, dont
l'essentiel (av-tools, figma, superpowers, web-back…) n'est jamais consulté. Pistes, de la plus
légère à la plus ciblée :
- sortie compacte (`JSON.stringify(v)` sans indentation) : ~10,6 Ko, −35 % ;
- `available` restreint aux ids et replis du mapping effectif (+ `unusable`, `missing`) : quelques
  centaines d'octets ; un mode `inventory --all` garde la liste complète pour le setup.

```json
{ "available": ["vue-developer","typescript-pro","writing-clean-code","developing-scss","reviewing-code","auditing-accessibility","auditing-performance","runtime-bug-reporter","thot:thot-read","web-front:figma-analyzer","web-front:type-generator"], "unusable": [], "missing": [] }
```
